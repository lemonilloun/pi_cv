# BNO085 в режиме UART-RVC: практическое руководство для реконструкции и навигации по помещению

**Платформа:** Raspberry Pi 5 + AI HAT+ (Hailo-8) · Camera Module 3 · GY-BNO08X (BNO085) через FT232RL на `/dev/ttyUSB0` · ESP8266 + TB6612FNG + N20 с магнитными энкодерами
**Пайплайн проекта:** DINOv2 + VGGT + CLIP → метрическая глубина → floor plan + объекты комнаты
**Роль IMU в проекте:** ориентация камеры (направление взгляда), выравнивание реконструкции по гравитации, направление движения, отбор ключевых кадров

---

## ⚠️ ЧИТАТЬ ПЕРВЫМ

**1. Самое ценное в RVC — это НЕ yaw, а pitch/roll.**
Углы наклона привязаны к гравитации и **не дрейфуют никогда**. Они дают абсолютную вертикаль для вашей реконструкции. VGGT и depth-модели выдают облако точек в произвольно наклонённой системе координат — без вертикали пол не найти, floor plan не построить, высоту объектов не измерить. IMU решает это одной строкой. Это главный аргумент, зачем модуль вообще нужен в вашем проекте.

**2. Yaw дрейфует ~0.5°/мин и не имеет абсолютной привязки.**
За 10-минутную сессию сканирования комнаты накопится ~5°. Yaw пригоден как **относительный курс между близкими кадрами** (в пределах 10–30 с — почти идеален) и как **prior для оценки поз**, но не как источник абсолютного направления на всю сессию. Долгосрочная привязка — только визуальная (повторное наблюдение объектов, loop closure).

**3. Из акселерометра RVC нельзя получить позицию или скорость.**
Ошибка наклона 0.5° → паразитное ускорение 0.086 м/с² → 0.43 м ошибки за 10 с (растёт как ½at²). Никакой фильтр это не лечит. Акселерометр в вашем проекте нужен для другого: детекция покоя, детекция вибрации/удара, вектор гравитации. Расстояние — с энкодеров, масштаб — с энкодеров и depth-модели.

**4. Направление движения вашего робота = yaw. Считать его из акселерометра не нужно.**
У дифференциального привода неголономная связь: робот физически может двигаться только вдоль собственной оси X. Направление движения в мире — это и есть курс (или курс + 180° при заднем ходе). Знак берётся с энкодеров. Никакого интегрирования.

**5. Обязательные фиксы до первого запуска.**
FTDI по умолчанию буферизует данные пачками по 16 мс — это ломает временную привязку кадров. Не двигайте робота 4–5 с после подачи питания на IMU — в этот момент оценивается смещение гироскопа. Yaw надо разворачивать (`unwrap`) до любых вычислений, иначе на переходе ±180° получите гигантские ложные скачки.

**6. Магнитометр может быть включён внутри RVC.**
RVC не даёт флагов, какой алгоритм фузии используется. Если магнитометр активен, магниты энкодеров N20 и токи моторов будут портить yaw. Обязательно прогнать Тест A (§5.1) — это 2 минуты и определяет всю дальнейшую стратегию работы с курсом.

## 1. Что RVC даёт и чего не даёт

### Есть

| Поле | Разрешение | Свойство | Ценность для проекта |
|---|---|---|---|
| **pitch** | 0.01° | не дрейфует, привязан к g | ⭐⭐⭐ вертикаль реконструкции |
| **roll** | 0.01° | не дрейфует, привязан к g | ⭐⭐⭐ вертикаль реконструкции |
| **yaw** | 0.01° | дрейф ~0.5°/мин, нет абс. нуля | ⭐⭐⭐ направление взгляда, prior поз |
| **accel x/y/z** | 1 мг | с гравитацией, body-frame | ⭐⭐ покой, вибрация, удар |
| **index** | 0–255 | ровно 100 Гц | ⭐⭐⭐ временная сетка, детект пропусков |

### Нет

| Чего нет | Последствие |
|---|---|
| Угловая скорость гироскопа | Восстанавливается из yaw фильтром (§7.3), качества хватает |
| Кватернион | Собирается из Эйлеровых углов (§7.1) |
| Магнитометр | Нет привязки к северу — не нужна |
| Флаги точности калибровки | Качество проверяется тестами §5 вручную |
| Метка времени устройства | Восстанавливается по счётчику index (§8) |
| Команды Save DCD / Tare / выбор режима фузии | Калибровка делается на хосте (§6) |

### Формат кадра

19 байт, **100 Гц, 115200 бод, 8N1**, little-endian.

| Байт | Поле | Масштаб |
|---|---|---|
| 0–1 | `0xAA 0xAA` | заголовок |
| 2 | index | uint8, инкремент каждый кадр |
| 3–4 | yaw | int16 × 0.01° |
| 5–6 | pitch | int16 × 0.01° |
| 7–8 | roll | int16 × 0.01° |
| 9–10 | accel X | int16 × 1 мг |
| 11–12 | accel Y | int16 × 1 мг |
| 13–14 | accel Z | int16 × 1 мг |
| 15–17 | reserved (MI/MR) | 0 |
| 18 | checksum | `sum(frame[2:18]) & 0xFF` |

Порядок применения поворотов: **yaw → pitch → roll**, то есть `R = Rz(yaw) · Ry(pitch) · Rx(roll)`.

Ускорение содержит гравитацию: в покое горизонтально Z ≈ +977 мг ≈ 1 g. Это проверка живости — если `|a| ≠ 9.8 м/с²` в покое, что-то не так с парсингом.

**Тест парсера на эталонном кадре из даташита** — прогнать до подключения железа:

```python
import struct
ref = bytes.fromhex('AAAADE01009 2FF25088DFEECFFD103000000E7'.replace(' ', ''))
assert len(ref) == 19
assert (sum(ref[2:18]) & 0xFF) == ref[18]           # checksum сходится
y, p, r, ax, ay, az = struct.unpack('<hhhhhh', ref[3:15])
assert (y * 0.01, p * 0.01, r * 0.01) == (0.01, -1.10, 20.85)
assert (ax, ay, az) == (-371, -20, 977)             # мг
print('парсер корректен')
```

Если эти assert проходят — байтовый разбор и checksum у вас точно правильные, и любые дальнейшие «странные значения» имеют другую причину (см. §14).

## 2. Роль IMU в вашем пайплайне

Ваш проект не VIO. Здесь IMU не оценивает позицию — он **аннотирует кадры и выпрямляет геометрию**.

| Задача пайплайна | Что даёт IMU | Как именно |
|---|---|---|
| Выравнивание облака точек | pitch, roll | Поворот, ставящий гравитацию вертикально → пол становится горизонтальным |
| Поиск плоскости пола | вертикаль | Вместо RANSAC по всему облаку — отбор точек с нормалью ∥ g |
| Floor plan (2D проекция) | вертикаль | Ортопроекция вдоль g даёт корректный план, а не косую тень |
| Высота объектов | вертикаль + пол | Метрическая высота от плоскости пола |
| Направление взгляда камеры | yaw | Азимут оптической оси для каждого кадра |
| Prior для VGGT / pose graph | Δyaw, Δpitch, Δroll | Относительное вращение между кадрами как ограничение |
| Отбор ключевых кадров | ω, accel | Не брать кадры при быстром вращении (смаз) и при вибрации |
| Разрешение неоднозначности | вертикаль | «Верх/низ» в семантике: потолок vs пол, стены vs мебель |
| Направление движения | yaw + знак с энкодеров | Вектор перемещения в мире |
| Ассоциация объектов между кадрами | Δyaw | Предсказание, куда сместился объект → сужение поиска для DINOv2-матчинга |

**Ключевая мысль:** VGGT восстанавливает позы с точностью до общего масштаба и в произвольной ориентации. Энкодеры дают метрический масштаб. IMU даёт абсолютную вертикаль и относительный курс. Вместе эти три источника закрывают всё, что нужно для метрически корректного плана комнаты.

## 3. Подготовка системы

### 3.1. Понижение задержки FTDI

FT232RL по умолчанию отдаёт данные в USB раз в 16 мс. На 100 Гц это значит: кадры приходят пачками по 1–2, интервалы прихода скачут от 0 до 16 мс. Это ломает привязку IMU к моментам съёмки кадров.

```bash
# Разово
echo 1 | sudo tee /sys/bus/usb-serial/devices/ttyUSB0/latency_timer
cat /sys/bus/usb-serial/devices/ttyUSB0/latency_timer   # должно быть 1

# Постоянно
sudo tee /etc/udev/rules.d/99-ftdi-low-latency.rules > /dev/null <<'EOF'
ACTION=="add", SUBSYSTEM=="usb-serial", DRIVER=="ftdi_sio", ATTR{latency_timer}="1"
EOF
sudo udevadm control --reload-rules && sudo udevadm trigger
```

### 3.2. Стабильное имя устройства

`/dev/ttyUSB0` меняется при переподключении. Привяжите по серийнику:

```bash
udevadm info -a -n /dev/ttyUSB0 | grep -m1 serial   # узнать ATTRS{serial}
```

```bash
sudo tee /etc/udev/rules.d/98-bno085.rules > /dev/null <<'EOF'
SUBSYSTEM=="tty", ATTRS{idVendor}=="0403", ATTRS{serial}=="ВАШ_СЕРИЙНИК", SYMLINK+="imu", ATTR{device/latency_timer}="1"
EOF
sudo udevadm control --reload-rules && sudo udevadm trigger
```

Дальше используйте `/dev/imu`.

### 3.3. Права доступа

```bash
sudo usermod -aG dialout $USER    # перелогиниться
```

### 3.4. Проверка живости

python3 -c "
import serial

d = s.read(200)
print('AA AA найдено:', d.count(b'\xaa\xaa'), 'раз в 200 байтах (ожидается ~10)')

### 3.5. Процедура включения — обязательно

BNO085 оценивает смещение гироскопа в покое сразу после старта.

1. Подать питание на IMU
2. **Робот неподвижен 5 секунд** — не катать, не поднимать, не трясти
3. Только после этого начинать движение

Нарушение этого пункта — самая частая причина «гироскоп врёт» и быстрого ухода курса.

### 3.6. Физический монтаж

| Требование | Почему |
|---|---|
| Жёсткий крепёж, без люфта и вибрации платы | Вибрация N20 попадает прямо в акселерометр |
| Оси IMU параллельны осям робота (X — вперёд) | Убирает лишний поворот из всех формул |
| ≥5 см от моторов и магнитов энкодеров | Магнитные помехи в yaw (если магнитометр активен) |
| Провода к FT232RL короткие, витые | Наводки от ШИМ |
| Питание IMU от Pi, не от силовой шины моторов | Просадки при разгоне моторов |
| Общая земля силовой и логической части | Иначе плавающие уровни на UART |

<a name="4"></a>
## 4. Протокол и надёжное чтение

### 4.1. Правила, нарушение которых даёт «мусорные данные»

1. **Всегда искать заголовок `AA AA`.** Чтение фиксированными блоками по 19 байт приводит к сдвигу на один байт — и все значения превращаются в шум.
2. **Всегда проверять checksum.** При несовпадении — сдвиг на 1 байт и поиск заголовка заново, а не отбрасывание всего блока.
3. **Не спать в цикле чтения.** `sleep(0.1)` при потоке 100 Гц копит буфер, вы читаете данные пятисекундной давности.
4. **Читать в отдельном потоке.** Основной поток занят камерой и инференсом — UART не должен зависеть от него.
5. **Хранить последние N отсчётов в кольцевом буфере.** Кадру камеры нужна ориентация в конкретный прошлый момент времени.

### 4.2. Модуль чтения `rvc_reader.py`

```python
"""
rvc_reader.py — надёжное чтение BNO085 UART-RVC.
Поток-читатель + кольцевой буфер + временная модель по index.
"""
import serial, struct, threading, time
import numpy as np
from collections import deque

MG_TO_MS2 = 9.80665 / 1000.0
DEG_TO_RAD = np.pi / 180.0


class RVCSample:
    __slots__ = ('index', 'yaw', 'pitch', 'roll', 'ax', 'ay', 'az',
                 't_host', 't_grid', 'seq')

    def __init__(self, index, yaw, pitch, roll, ax, ay, az, t_host, seq):
        self.index = index          # 0..255 из кадра
        self.yaw = yaw              # рад, unwrapped
        self.pitch = pitch          # рад
        self.roll = roll            # рад
        self.ax, self.ay, self.az = ax, ay, az   # м/с², body, с гравитацией
        self.t_host = t_host        # время прихода (ненадёжное)
        self.t_grid = None          # восстановленное время (заполняется моделью)
        self.seq = seq              # сквозной счётчик без переполнения


class RVCReader:
    def __init__(self, port='/dev/imu', baud=115200, buflen=6000):
        self.ser = serial.Serial(port, baud, timeout=0.02)
        self.buf = deque(maxlen=buflen)      # ~60 с истории
        self.lock = threading.Lock()
        self.running = False
        self.stats = {'ok': 0, 'bad_crc': 0, 'dropped': 0, 'resync': 0}
        self._raw = bytearray()
        self._seq = 0
        self._last_index = None
        self._yaw_prev_raw = None
        self._yaw_unwrap = 0.0
        # временная модель: t_grid = a * seq + b
        self._clock_a = 0.01
        self._clock_b = None
        self._fit_pts = deque(maxlen=2000)

    # ---------- парсинг ----------
    def _parse(self, t_host):
        out = []
        b = self._raw
        i = 0
        n = len(b)
        while i <= n - 19:
            if b[i] == 0xAA and b[i + 1] == 0xAA:
                fr = b[i:i + 19]
                if (sum(fr[2:18]) & 0xFF) == fr[18]:
                    idx = fr[2]
                    yaw_r, pit_r, rol_r, ax_r, ay_r, az_r = struct.unpack('<hhhhhh', bytes(fr[3:15]))
                    out.append(self._make(idx, yaw_r, pit_r, rol_r,
                                          ax_r, ay_r, az_r, t_host))
                    i += 19
                    continue
                else:
                    self.stats['bad_crc'] += 1
                    self.stats['resync'] += 1
                    i += 1
                    continue
            i += 1
        del b[:i]
        return out

    def _make(self, idx, yaw_r, pit_r, rol_r, ax_r, ay_r, az_r, t_host):
        # детект пропущенных кадров по index
        if self._last_index is not None:
            gap = (idx - self._last_index) & 0xFF
            if gap == 0:
                gap = 256
            if gap > 1:
                self.stats['dropped'] += gap - 1
                self._seq += gap - 1
        self._last_index = idx
        self._seq += 1

        yaw_deg = yaw_r * 0.01
        # разворот через ±180°
        if self._yaw_prev_raw is not None:
            d = yaw_deg - self._yaw_prev_raw
            if d > 180.0:
                self._yaw_unwrap -= 360.0
            elif d < -180.0:
                self._yaw_unwrap += 360.0
        self._yaw_prev_raw = yaw_deg
        yaw_cont = (yaw_deg + self._yaw_unwrap) * DEG_TO_RAD

        s = RVCSample(
            idx, yaw_cont, pit_r * 0.01 * DEG_TO_RAD, rol_r * 0.01 * DEG_TO_RAD,
            ax_r * MG_TO_MS2, ay_r * MG_TO_MS2, az_r * MG_TO_MS2,
            t_host, self._seq)
        self._update_clock(s)
        self.stats['ok'] += 1
        return s

    # ---------- временная модель ----------
    def _update_clock(self, s):
        self._fit_pts.append((s.seq, s.t_host))
        if self._clock_b is None:
            self._clock_b = s.t_host - self._clock_a * s.seq
        if len(self._fit_pts) >= 200 and s.seq % 50 == 0:
            arr = np.array(self._fit_pts)
            # робастно: медианная регрессия по краям окна
            k = len(arr) // 4
            x1, y1 = arr[:k, 0].mean(), arr[:k, 1].mean()
            x2, y2 = arr[-k:, 0].mean(), arr[-k:, 1].mean()
            if x2 > x1:
                a = (y2 - y1) / (x2 - x1)
                if 0.008 < a < 0.012:          # санитарный диапазон
                    self._clock_a = a
                    self._clock_b = arr[:, 1].mean() - a * arr[:, 0].mean()
        s.t_grid = self._clock_a * s.seq + self._clock_b

    # ---------- поток ----------
    def _loop(self):
        while self.running:
            chunk = self.ser.read(256)
            t = time.monotonic()
            if not chunk:
                continue
            self._raw.extend(chunk)
            samples = self._parse(t)
            if samples:
                with self.lock:
                    self.buf.extend(samples)

    def start(self):
        self.ser.reset_input_buffer()
        self.running = True
        self.th = threading.Thread(target=self._loop, daemon=True)
        self.th.start()

    def stop(self):
        self.running = False
        self.th.join(timeout=1.0)
        self.ser.close()

    # ---------- доступ ----------
    def latest(self):
        with self.lock:
            return self.buf[-1] if self.buf else None

    def window(self, n):
        with self.lock:
            return list(self.buf)[-n:]

    def at_time(self, t_query):
        """Интерполяция ориентации на произвольный момент t (monotonic)."""
        with self.lock:
            arr = list(self.buf)
        if len(arr) < 2:
            return None
        ts = np.array([s.t_grid for s in arr])
        j = np.searchsorted(ts, t_query)
        if j <= 0 or j >= len(arr):
            return None
        a, b = arr[j - 1], arr[j]
        span = b.t_grid - a.t_grid
        w = 0.0 if span <= 0 else (t_query - a.t_grid) / span
        return {
            'yaw':   a.yaw + w * (b.yaw - a.yaw),
            'pitch': a.pitch + w * (b.pitch - a.pitch),
            'roll':  a.roll + w * (b.roll - a.roll),
            't': t_query,
            'gap': span,
        }
```

Разворот yaw делается на сырых градусах до конвертации — так переход через ±180° ловится корректно.

### 4.3. Проверка качества потока

```python
r = RVCReader('/dev/imu'); r.start()
time.sleep(60); r.stop()
print(r.stats)
```

| Метрика | Норма | Если хуже |
|---|---|---|
| `ok` | ≈6000 за 60 с | Проверить latency_timer, скорость чтения |
| `bad_crc` | <1% от ok | Проверить провода, землю, наводки от моторов |
| `dropped` | <0.5% | Читающий поток не успевает — убрать нагрузку |
| `_clock_a` | 0.0099–0.0101 | Проблема с потоком или с USB |

### 5.1. Тест A — активен ли магнитометр (2 минуты, критичный)

Модуль неподвижен. Записать yaw 30 с. Поднести отвёртку или магнит на 3 см на 20 с. Убрать, записать ещё 30 с.

| Результат | Вывод | Стратегия |
|---|---|---|
| yaw сдвинулся на >2° и вернулся | Магнитометр активен | Yaw использовать **только как относительный** на коротких окнах; рядом с моторами не доверять; повысить приоритет визуальной коррекции |
| yaw не отреагировал (<0.5°) | Работает как Game Rotation Vector | Yaw надёжен как относительный курс на минутах, дрейф предсказуем |

## 7. Производные величины

### 7.1. Матрица поворота и кватернион

```python
def rvc_to_R(yaw, pitch, roll):
    """RVC: yaw -> pitch -> roll.  R = Rz(yaw) @ Ry(pitch) @ Rx(roll)
    Переводит вектор из body в world (world: Z вверх)."""
    cy, sy = np.cos(yaw), np.sin(yaw)
    cp, sp = np.cos(pitch), np.sin(pitch)
    cr, sr = np.cos(roll), np.sin(roll)
    Rz = np.array([[cy, -sy, 0], [sy, cy, 0], [0, 0, 1]])
    Ry = np.array([[cp, 0, sp], [0, 1, 0], [-sp, 0, cp]])
    Rx = np.array([[1, 0, 0], [0, cr, -sr], [0, sr, cr]])
    return Rz @ Ry @ Rx


def R_to_quat(R):
    """xyzw."""
    tr = np.trace(R)
    if tr > 0:
        s = 0.5 / np.sqrt(tr + 1.0)
        w = 0.25 / s
        x = (R[2, 1] - R[1, 2]) * s
        y = (R[0, 2] - R[2, 0]) * s
        z = (R[1, 0] - R[0, 1]) * s
    else:
        i = int(np.argmax(np.diag(R)))
        j, k = (i + 1) % 3, (i + 2) % 3
        s = 2.0 * np.sqrt(1.0 + R[i, i] - R[j, j] - R[k, k])
        q = np.zeros(3)
        q[i] = 0.25 * s
        q[j] = (R[j, i] + R[i, j]) / s
        q[k] = (R[k, i] + R[i, k]) / s
        w = (R[k, j] - R[j, k]) / s
        x, y, z = q
    q = np.array([x, y, z, w])
    return q / np.linalg.norm(q)
```

### 7.2. Вектор гравитации и выравнивающий поворот — ⭐ главное для проекта

Гравитация в body-фрейме зависит **только от pitch и roll**, yaw в неё не входит. Значит вектор вертикали не дрейфует.

```python
def gravity_in_body(pitch, roll):
    """Единичный вектор 'вниз' в системе координат IMU."""
    cp, sp = np.cos(pitch), np.sin(pitch)
    cr, sr = np.cos(roll), np.sin(roll)
    # g_body = R(yaw=0)^T @ [0,0,-1]
    return np.array([sp, -cp * sr, -cp * cr])


def level_rotation(pitch, roll):
    """Поворот, приводящий облако точек к горизонту (Z вверх),
    НЕ меняя курс. Это R(yaw=0, pitch, roll) = Ry(pitch) @ Rx(roll).
    Применяется к точкам: P_level = R_level @ P_body"""
    cp, sp = np.cos(pitch), np.sin(pitch)
    cr, sr = np.cos(roll), np.sin(roll)
    Ry = np.array([[cp, 0, sp], [0, 1, 0], [-sp, 0, cp]])
    Rx = np.array([[1, 0, 0], [0, cr, -sr], [0, sr, cr]])
    return Ry @ Rx
```

**Проверка корректности (обязательно прогнать один раз):**

```python
# g_body должен переходить ровно в [0, 0, -1]
p, r = np.deg2rad(7.0), np.deg2rad(-4.0)
assert np.allclose(level_rotation(p, r) @ gravity_in_body(p, r),
                   [0, 0, -1], atol=1e-9)
```

Практическая проверка: примените `level_rotation` к облаку из depth-модели, снятому в комнате с горизонтальным полом. Точки пола должны лечь в плоскость `Z = const` с разбросом в пределах шума depth-модели.

### 7.3. Угловая скорость из yaw

Наивная разность `(yaw[n] − yaw[n−1]) / 0.01` даёт шум ~1°/с из-за квантования 0.01°. Причинный фильтр Калмана 2-го порядка решает это без задержки:

```python
class YawRateKF:
    """Состояние [theta, omega]. Вход: unwrapped yaw в радианах, 100 Гц."""

    def __init__(self, dt=0.01, sigma_theta_deg=0.03, q_alpha=2.0):
        self.dt = dt
        self.x = np.zeros(2)
        self.P = np.diag([1e-2, 1e-1])
        self.F = np.array([[1.0, dt], [0.0, 1.0]])
        # q_alpha — СКО углового ускорения, рад/с². См. таблицу подбора ниже.
        self.Q = (q_alpha ** 2) * np.array([[dt**4 / 4, dt**3 / 2],
                                            [dt**3 / 2, dt**2]])
        self.H = np.array([[1.0, 0.0]])
        self.R = np.array([[np.deg2rad(sigma_theta_deg) ** 2]])
        self.init = False

    def step(self, theta):
        if not self.init:
            self.x[0] = theta
            self.init = True
            return self.x.copy()
        self.x = self.F @ self.x
        self.P = self.F @ self.P @ self.F.T + self.Q
        y = np.array([theta]) - self.H @ self.x
        S = self.H @ self.P @ self.H.T + self.R
        K = (self.P @ self.H.T) / S[0, 0]
        self.x = self.x + K.ravel() * y[0]
        self.P = (np.eye(2) - np.outer(K, self.H)) @ self.P
        return self.x.copy()      # [theta_сглаженный, omega]
```

`sigma_theta_deg` берите из Теста B (обычно 0.02–0.05).

**Подбор `q_alpha`** (проверено симуляцией на реалистичном профиле движения, σ_yaw = 0.02°, квантование 0.01°):

| `q_alpha` | Шум ω | Отклик на скачок (до 90%) | Когда |
|---|---|---|---|
| 1.0 | 0.45 °/с | 40 мс | Плавное сканирование, приоритет — гладкость |
| **2.0** | **0.77 °/с** | **20 мс** | **Рекомендуемый по умолчанию** |
| 4.0 | 1.24 °/с | 10 мс | Резкие развороты на месте |
| 8.0 | 1.93 °/с | 10 мс | Только если робот очень динамичный |
| 20+ | >4 °/с | 10 мс | ❌ Хуже наивного дифференцирования |

Для сравнения: наивная разность `(yaw[n] − yaw[n−1])/dt` даёт **σ ≈ 3.0 °/с**. То есть `q_alpha = 2` снижает шум примерно вчетверо при нулевой задержке.

Для офлайн-обработки записей (когда доступны будущие отсчёты) точнее Savitzky-Golay, σ ≈ 0.20 °/с:
```python
from scipy.signal import savgol_filter
omega = savgol_filter(yaw, 11, 2, deriv=1, delta=0.01)   # требует ±50 мс контекста
```
В реальном времени он неприменим — нужны отсчёты «из будущего».

### 7.4. Детектор состояния движения

```python
def motion_state(window, cfg):
    """window — список RVCSample за последние ~0.3 с (30 отсчётов)."""
    a = np.array([[s.ax, s.ay, s.az] for s in window])
    mag = np.linalg.norm(a, axis=1)
    yaw = np.array([s.yaw for s in window])
    dt = window[-1].t_grid - window[0].t_grid
    omega = abs(yaw[-1] - yaw[0]) / max(dt, 1e-3)

    std_a = float(np.std(mag))
    stationary = (std_a < cfg['stationary_std_accel'] and
                  np.rad2deg(omega) < cfg['stationary_omega_dps'])
    return {
        'stationary': stationary,
        'std_accel': std_a,
        'omega_dps': float(np.rad2deg(omega)),
        'vibration': std_a > 0.4,
        'impact': float(mag.max()) > 13.0,     # ~3 м/с² сверх g
    }
```

### 7.5. Что использовать для отбора ключевых кадров

Кадр годится для DINOv2/VGGT/depth, если:

| Условие | Порог | Причина |
|---|---|---|
| `omega_dps` | < 15 °/с | Выше — смаз при экспозиции 1/30 с |
| `vibration` | False | Смаз и шум в depth |
| `impact` | False | Резкий сдвиг между строками rolling shutter |

## 8. Синхронизация с камерой

Без этого весь блок §10 не работает: если ориентация привязана к кадру с ошибкой 50 мс, а робот вращается на 30 °/с, ошибка курса кадра будет 1.5°.

### 8.1. Схема

1. IMU-поток пишет отсчёты с восстановленным `t_grid` (модель `t = a·seq + b` из §4.2).
2. Камера отдаёт кадр с меткой времени. У Picamera2 берите **`SensorTimestamp`** из метаданных кадра, а не `time.monotonic()` после `capture_array()` — второе включает время инференса и джиттер.
3. Для каждого кадра вызывается `reader.at_time(t_frame + t_offset)`.

```python
from picamera2 import Picamera2

picam = Picamera2()
picam.configure(picam.create_still_configuration(main={"size": (1536, 864)}))
picam.set_controls({"AfMode": 0, "LensPosition": 3.0})   # автофокус ЗАФИКСИРОВАН
picam.start()

request = picam.capture_request()
arr = request.make_array("main")
md = request.get_metadata()
request.release()

# SensorTimestamp в наносекундах, та же база, что CLOCK_MONOTONIC
t_frame = md['SensorTimestamp'] / 1e9
# середина экспозиции — правильная точка привязки
t_frame += md.get('ExposureTime', 0) * 1e-6 / 2.0

pose = reader.at_time(t_frame + cfg['camera_imu']['t_offset_s'])
```

### 8.2. Оценка временного сдвига `t_offset`

Если `SensorTimestamp` доступен, сдвиг обычно близок к нулю, но проверить надо.

**Процедура (10 минут).** Робот вращается на месте вперёд-назад с переменной скоростью, 60 с. Для каждого кадра считается визуальное вращение (по оптическому потоку или гомографии между соседними кадрами) → `omega_visual(t)`. Из IMU берётся `omega_imu(t)`. Дальше — кросс-корреляция:

```python
from scipy.signal import correlate
# оба сигнала ресемплированы на общую сетку с шагом 5 мс
c = correlate(omega_visual - omega_visual.mean(),
              omega_imu - omega_imu.mean(), mode='full')
lag_samples = c.argmax() - (len(omega_imu) - 1)
t_offset = lag_samples * 0.005
print(f't_offset = {t_offset*1000:.1f} мс')
```

Норма: |t_offset| < 30 мс. Записать в `imu_calib.yaml`.

### 8.3. Что писать в каждый кадр

Минимум: `yaw, pitch, roll` на момент середины экспозиции, `omega` (для оценки смаза), `t_grid`, `gap` (разница времени между соседними IMU-отсчётами — если >30 мс, ориентация интерполирована грубо и доверие ниже).

## 9. Калибровка camera↔IMU

Нужен поворот `R_cam_imu`, переводящий из системы IMU в систему камеры. Kalibr здесь избыточен — у вас нет требований VIO к точности. Достаточно двух подходов.

### 9.1. Быстрый способ — по монтажу

Если камера смотрит вперёд, а IMU установлен осями параллельно роботу, `R_cam_imu` — это просто перестановка осей. Стандартная система координат камеры: X вправо, Y вниз, Z вперёд. Система робота/IMU: X вперёд, Y влево, Z вверх.

```python
R_cam_imu = np.array([
    [ 0, -1,  0],   # cam X (вправо)  = -robot Y
    [ 0,  0, -1],   # cam Y (вниз)    = -robot Z
    [ 1,  0,  0],   # cam Z (вперёд)  =  robot X
], dtype=float)
```

Ошибка такого способа — величина неточности монтажа, обычно 1–3°.

### 9.2. Точный способ — через плоскость пола из depth-модели

Это даёт настоящую калибровку и использует то, что у вас уже есть в пайплайне.

1. Снять 15–25 кадров комнаты **в разных ориентациях робота** (разный yaw, и обязательно несколько с наклоном — заехать колесом на книжку, чтобы pitch/roll различались на 5–15°).
2. Для каждого кадра прогнать depth-модель → облако точек в системе камеры.
3. Найти плоскость пола RANSAC → нормаль `n_cam` (нормировать, направить вверх).
4. Из IMU для того же кадра взять `g_body = gravity_in_body(pitch, roll)`, вертикаль вверх `u_imu = −g_body`.
5. Решить задачу Кабша: найти `R`, минимизирующий `Σ ‖ R · u_imu,k − n_cam,k ‖²`.

```python
def kabsch(A, B):
    """A, B: (N,3) единичные векторы. Возвращает R: R @ A[i] ≈ B[i]."""
    H = A.T @ B
    U, S, Vt = np.linalg.svd(H)
    d = np.sign(np.linalg.det(Vt.T @ U.T))
    D = np.diag([1.0, 1.0, d])
    return Vt.T @ D @ U.T

U_imu = np.stack(u_imu_list)     # (N,3)
N_cam = np.stack(n_cam_list)     # (N,3)
R_cam_imu = kabsch(U_imu, N_cam)

# остаточная ошибка
ang = np.rad2deg(np.arccos(np.clip(
    np.einsum('ij,ij->i', (R_cam_imu @ U_imu.T).T, N_cam), -1, 1)))
print(f'остаток: медиана {np.median(ang):.2f}°, макс {ang.max():.2f}°')
```

**Критично:** без вариации наклона задача вырождена — все `u_imu` окажутся одинаковыми, и вращение вокруг вертикали не определится. Обязательно наклонять робота.

Приемлемый результат: медианный остаток <2°.

### 9.3. Yaw-компонента

Кабш по гравитации определяет только 2 из 3 степеней свободы (вращение вокруг вертикали остаётся свободным). Yaw-составляющую `R_cam_imu` берите из монтажа (§9.1) или уточните так: поверните робота ровно на 90°, сравните `Δyaw` от IMU с визуальным поворотом камеры (по гомографии или по VGGT-позам). Разница — поправка.

## 10. Интеграция в пайплайн реконструкции

### 10.1. Выравнивание по гравитации — делать первым

Это одно преобразование, которое кардинально улучшает всё остальное.

```python
def align_cloud_to_gravity(points_cam, pitch, roll, R_cam_imu):
    """points_cam: (N,3) в системе камеры (из depth-модели или VGGT).
    Возвращает облако в системе, где Z направлен вверх по гравитации."""
    u_imu = -gravity_in_body(pitch, roll)          # 'вверх' в системе IMU
    u_cam = R_cam_imu @ u_imu                      # 'вверх' в системе камеры
    z = np.array([0.0, 0.0, 1.0])

    v = np.cross(u_cam, z)
    s, c = np.linalg.norm(v), float(np.dot(u_cam, z))
    if s < 1e-8:
        R = np.eye(3) if c > 0 else -np.eye(3)
    else:
        vx = np.array([[0, -v[2], v[1]], [v[2], 0, -v[0]], [-v[1], v[0], 0]])
        R = np.eye(3) + vx + vx @ vx * ((1 - c) / s**2)
    return points_cam @ R.T, R
```

Функция применяет **минимальный** поворот, приводящий вертикаль к оси Z. Курс при этом остаётся произвольным: облака от разных кадров будут выровнены по вертикали, но повёрнуты друг относительно друга. Чтобы свести их в единую систему координат комнаты, после выравнивания примените поворот вокруг Z на `view_azimuth(yaw)` из §10.5.

**Что это сразу даёт:**

| Задача | До выравнивания | После |
|---|---|---|
| Поиск пола | RANSAC по всему облаку, часто цепляется за стол | Отбор точек с нормалью ∥ Z, затем гистограмма по Z — пик = пол |
| Floor plan | Косая проекция, стены не параллельны | Честная ортопроекция вдоль Z |
| Высота объектов | Не определена | `h = Z − Z_пол`, метры |
| Стены | Не отличить от наклонных поверхностей | Плоскости с нормалью ⊥ Z |
| Семантика верх/низ | Из контекста | Потолок = высокий Z, пол = низкий |

### 10.2. Поиск пола после выравнивания

```python
def find_floor(points_level, normals=None, bin_h=0.02):
    """points_level — облако, выровненное по гравитации."""
    if normals is not None:
        mask = np.abs(normals[:, 2]) > 0.9      # почти горизонтальные
        cand = points_level[mask]
    else:
        cand = points_level
    hist, edges = np.histogram(cand[:, 2], bins=np.arange(
        cand[:, 2].min(), cand[:, 2].max() + bin_h, bin_h))
    # пол — самый низкий значимый пик
    sig = np.where(hist > 0.15 * hist.max())[0]
    z_floor = edges[sig[0]] + bin_h / 2
    return float(z_floor)
```

Высота камеры над полом — известная константа вашего робота. Это **отличная проверка масштаба depth-модели**: если `−z_floor` в облаке не совпадает с реальной высотой установки камеры, масштаб depth надо корректировать. Эту поправку можно применять к каждому кадру.

### 10.3. Ориентационный prior для VGGT

VGGT восстанавливает относительные позы. IMU даёт независимую оценку относительного вращения между кадрами:

```python
def imu_relative_rotation(pose_a, pose_b, R_cam_imu):
    """Относительный поворот камеры между двумя кадрами по данным IMU."""
    R_a = rvc_to_R(pose_a['yaw'], pose_a['pitch'], pose_a['roll'])
    R_b = rvc_to_R(pose_b['yaw'], pose_b['pitch'], pose_b['roll'])
    R_rel_imu = R_a.T @ R_b
    return R_cam_imu @ R_rel_imu @ R_cam_imu.T
```

Применения:
- **Проверка результата VGGT.** Сравнить с полученным из VGGT относительным вращением. Расхождение >10° на паре кадров, снятых с интервалом <5 с — признак ошибки сопоставления. Такую пару стоит исключить или понизить её вес.
- **Инициализация оптимизации поз.** Дать VGGT/pose-graph стартовую оценку вращения.
- **Ограничение в pose graph.** Добавить рёбра «относительное вращение» с ковариацией, полученной из Теста B (для интервалов до 30 с σ ≈ 0.2–0.5°).
- **Разрешение симметрии.** В комнатах с повторяющимися элементами (одинаковые двери, шкафы) визуальный матчинг ошибается; курс от IMU отсекает неверные гипотезы.

### 10.4. Ускорение ассоциации объектов

При повороте на Δyaw объект смещается по горизонтали примерно на `Δu ≈ f_x · Δyaw` пикселей (для малых углов, f_x — фокус в пикселях). Это позволяет:

```python
def predict_shift(delta_yaw, delta_pitch, fx, fy, sign_u=-1.0, sign_v=+1.0):
    """Ожидаемое смещение проекции точки, пиксели (малые углы).
    sign_u/sign_v зависят от вашей ориентации камеры относительно IMU —
    определите их эмпирически: поверните робота на известный угол и
    посмотрите, в какую сторону поехала картинка."""
    return sign_u * fx * delta_yaw, sign_v * fy * delta_pitch
```

Формула верна только для малых углов и для точек вблизи оптической оси. Для широких углов и краёв кадра используйте полноценное перепроецирование через `R_rel` из §10.3 и интринсики камеры.

Использование: перед матчингом DINOv2-дескрипторов между кадрами сузьте зону поиска до окрестности предсказанной позиции. Это ускоряет поиск и резко снижает число ложных соответствий, особенно на однотонных стенах.

### 10.5. Направление взгляда для floor plan

Для каждого ключевого кадра азимут оптической оси камеры в системе комнаты:

```python
def view_azimuth(yaw, yaw_offset_room):
    """yaw_offset_room — калибровка нуля курса относительно комнаты."""
    return (yaw - yaw_offset_room + np.pi) % (2 * np.pi) - np.pi
```

`yaw_offset_room` задаётся один раз: поставьте робота параллельно выбранной стене, запишите текущий yaw — это ноль системы координат комнаты. Дальше все азимуты кадров становятся сопоставимыми, и на floor plan можно рисовать конусы обзора.

### 10.6. Роли источников данных

| Величина | Источник | Точность |
|---|---|---|
| Вертикаль (up) | **IMU pitch/roll** | 1–2°, без дрейфа |
| Относительный курс (<30 с) | **IMU yaw** | 0.2–0.5° |
| Абсолютный курс (вся сессия) | Визуальная привязка + IMU | зависит от коррекции |
| Метрический масштаб | **Энкодеры** + высота камеры над полом | 2–5% |
| Пройденное расстояние | **Энкодеры** | 2–5%, хуже при буксовании |
| Относительная поза кадров | **VGGT** + prior от IMU | зависит от сцены |
| Метрическая глубина | **Depth-модель** + масштабирование по полу | 5–15% |
| Позиция в комнате | Счисление + визуальная привязка | растёт без коррекции |

<a name="12"></a>
## 12. Направление движения и траектория

### 12.1. Ключевое упрощение

Дифференциальный привод неголономен: робот движется только вдоль своей продольной оси. Поэтому:

```
направление движения в мире = yaw            (вперёд)
направление движения в мире = yaw + 180°     (назад)
```

Знак определяется по энкодерам, не по акселерометру. Никакого интегрирования ускорения.

### 12.2. Счисление пути

```python
class DeadReckoning:
    """Курс от IMU, расстояние от энкодеров."""

    def __init__(self, x0=0.0, y0=0.0, yaw_ref=0.0):
        self.x, self.y = x0, y0
        self.yaw_ref = yaw_ref        # ноль системы координат комнаты
        self.path = []

    def update(self, yaw_imu, d_left, d_right):
        """d_left, d_right — приращения пути колёс в метрах (со знаком)."""
        ds = 0.5 * (d_left + d_right)
        th = yaw_imu - self.yaw_ref
        # интегрирование по средней ориентации отрезка
        self.x += ds * np.cos(th)
        self.y += ds * np.sin(th)
        self.path.append((self.x, self.y, th))
        return self.x, self.y, th
```

Ошибка позиции здесь — это ошибка расстояния (энкодеры, 2–5%) плюс интеграл ошибки курса. При дрейфе 0.5 °/мин через 5 минут курс уйдёт на 2.5°, что на 20 метрах пути даёт ~0.9 м бокового смещения. Для построения плана комнаты это много — нужна визуальная коррекция (§13).

### 12.3. Автокалибровка колеи

Побочная, но очень полезная функция IMU. Пустите робота по кругу с постоянными `v_L ≠ v_R`, дождитесь установившегося вращения:

```
W_истинная = (v_R − v_L) / ω_imu
```

Это убирает главную систематическую ошибку одометрии дифференциального привода. Проверить: после коррекции курс, посчитанный из энкодеров, должен совпадать с IMU в пределах 1–2° на полном обороте.

### 12.4. Детекция буксования

```python
def slip_check(omega_imu, v_left, v_right, W, thresh_dps=8.0):
    omega_enc = (v_right - v_left) / W
    diff = np.rad2deg(abs(omega_enc - omega_imu))
    return diff > thresh_dps, diff
```

При срабатывании: пометить кадр `slip_flag: true`, не доверять приращению одометрии на этом отрезке, а курс брать только с IMU.

<a name="13"></a>
## 13. Коррекция дрейфа по визуальным данным

Дрейф курса 0.5 °/мин надо чем-то ограничивать. У вас для этого уже есть весь инструментарий.

### 13.1. Иерархия по надёжности

| Способ | Что даёт | Затраты | Точность |
|---|---|---|---|
| **ArUco/AprilTag на стенах** | абсолютные x, y, yaw | наклеить маркеры, OpenCV на CPU | 1–2 см, <1° |
| **Направления стен (Manhattan)** | абсолютный yaw по модулю 90° | плоскости из depth | 1–2° |
| **Повторное наблюдение объектов** | относительная поправка | CLIP/DINOv2, уже есть | 2–5° |
| **VGGT loop closure** | полная поправка позы | тяжёлый инференс | зависит от сцены |

### 13.2. Манхэттенское выравнивание — лучший вариант без маркеров

Комната почти всегда имеет стены под 90°. После выравнивания по гравитации (§10.1) стены становятся вертикальными плоскостями, и их нормали лежат в горизонтальной плоскости. Гистограмма азимутов этих нормалей по модулю 90° даёт **абсолютную привязку курса к геометрии комнаты**:

```python
def manhattan_yaw_correction(wall_normals_level):
    """wall_normals_level: (N,3) нормали вертикальных плоскостей
    в выровненном по гравитации облаке."""
    az = np.arctan2(wall_normals_level[:, 1], wall_normals_level[:, 0])
    az_mod = np.mod(az, np.pi / 2)          # свернуть в [0, 90°)
    # круговая медиана на окружности удвоенного угла
    c = np.mean(np.cos(4 * az_mod))
    s = np.mean(np.sin(4 * az_mod))
    offset = np.arctan2(s, c) / 4.0
    strength = np.hypot(c, s)               # 0..1, мера уверенности
    return offset, strength
```

При `strength > 0.7` (стены уверенно найдены) поправку можно применять к yaw. Это даёт курс, привязанный к комнате, с точностью 1–2°, и **не накапливает ошибку**.

### 13.3. Схема совместной работы

```
IMU yaw (гладкий, 100 Гц, дрейф 0.5°/мин)
        │
        ├──> высокая частота: относительный курс между кадрами  ─┐
        │                                                        ├──> курс кадра
Манхэттен / маркеры (редко, точно, без дрейфа) ──────────────────┘
        (медленная коррекция смещения b_yaw)
```

Простейшая реализация — экспоненциальная коррекция смещения:

```python
class YawDriftCorrector:
    def __init__(self, alpha=0.02):
        self.bias = 0.0
        self.alpha = alpha       # медленная адаптация, чтобы не дёргать курс

    def correct(self, yaw_imu):
        return yaw_imu - self.bias

    def observe(self, yaw_imu, yaw_absolute, weight=1.0):
        """yaw_absolute — курс из манхэттена или маркера."""
        err = (yaw_imu - self.bias) - yaw_absolute
        err = (err + np.pi) % (2 * np.pi) - np.pi
        self.bias += self.alpha * weight * err
```

`alpha` малое: курс должен оставаться гладким для реконструкции, резкие скачки создадут разрывы в pose graph.

## Приложение A — минимальный рабочий пример

```python
import time, yaml, numpy as np
from rvc_reader import RVCReader, rvc_to_R, gravity_in_body

cfg = yaml.safe_load(open('imu_calib.yaml'))
mount = cfg['mount']
p_off = np.deg2rad(mount['pitch_offset_deg'])
r_off = np.deg2rad(mount['roll_offset_deg'])

reader = RVCReader(cfg['port'])
reader.start()

print('Стабилизация IMU, не двигать робота...')
time.sleep(5.0)
print('Готово.')

try:
    while True:
        s = reader.latest()
        if s is None:
            time.sleep(0.05)
            continue
        pitch = s.pitch - p_off
        roll  = s.roll  - r_off
        yaw   = s.yaw * mount['k_yaw'] * mount['yaw_sign']

        up_imu = -gravity_in_body(pitch, roll)
        print(f'yaw={np.rad2deg(yaw):8.2f}°  '
              f'pitch={np.rad2deg(pitch):6.2f}°  '
              f'roll={np.rad2deg(roll):6.2f}°  '
              f'up={up_imu.round(3)}')
        time.sleep(0.2)
except KeyboardInterrupt:
    reader.stop()
    print(reader.stats)
```
